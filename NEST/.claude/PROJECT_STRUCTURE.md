# Project Structure

```
src/
├── main.ts                  ← Bootstrap: registers global pipes, filters, guards
├── app.module.ts            ← Root module — imports ConfigModule + feature modules
├── modules/                 ← One sub-folder per feature
│   └── <feature>/
│       ├── <feature>.module.ts
│       ├── <feature>.controller.ts
│       ├── <feature>.service.ts
│       └── dto/             ← Request/response DTOs for this feature
├── common/                  ← Shared NestJS primitives
│   ├── filters/             ← Exception filters (e.g. http-exception.filter.ts)
│   ├── guards/              ← Auth/role guards (e.g. jwt-auth.guard.ts)
│   ├── interceptors/        ← Response transform, logging interceptors
│   ├── pipes/               ← Custom validation pipes
│   └── decorators/          ← Custom param/method decorators
├── config/                  ← Env validation schema
└── types/                   ← Shared TypeScript interfaces, enums

requirements/                ← Feature requirement docs (generated by /plan-feature)
docs/                        ← Generated documentation (generated by /document)
```

## Rules

- Each feature module must be self-contained — controllers, services, and DTOs stay in their feature folder
- `common/` contains only reusable, feature-agnostic NestJS primitives
- Services must not import from controllers or other modules' controllers
- `config/` is the only place allowed to define env var validation schemas
- Test files live next to the file they test: `user.service.ts` → `user.service.spec.ts`
- e2e tests live in `test/` at the project root
