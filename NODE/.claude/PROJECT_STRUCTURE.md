# Project Structure

```
src/
├── index.ts          ← Entry point — starts the server, nothing else
├── app.ts            ← Express app setup, middleware registration, router mounting
├── routes/           ← Route definitions only (express.Router), no logic
├── controllers/      ← Request/response handling, calls services
├── services/         ← All business logic, DB access, outbound HTTP
├── middleware/       ← Express middleware (auth, validation, error handling)
├── models/           ← Data models, Zod schemas, DB schema types
├── lib/              ← Pure utility functions (no Express, no DB)
├── types/            ← TypeScript interfaces, types, enums
└── config/           ← Env var loading and app configuration

requirements/         ← Feature requirement docs (generated by /plan-feature)
docs/                 ← Generated documentation (generated by /document)
```

## Rules

- `routes/` files only import from `controllers/` — never services directly
- `controllers/` import from `services/` and `middleware/` only
- `services/` must not import from `controllers/`, `routes/`, or `middleware/`
- `lib/` must have zero Express or DB imports
- `config/` is the only place allowed to read `process.env`
- Test files live next to the file they test: `userService.ts` → `userService.test.ts`
