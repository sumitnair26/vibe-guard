# Project Structure

```
src/
├── main/
│   ├── java/com/example/app/
│   │   ├── AppApplication.java      ← Main entry point (@SpringBootApplication)
│   │   ├── config/                  ← @Configuration beans (Security, RestClient, etc.)
│   │   ├── controller/              ← @RestController classes (HTTP only)
│   │   ├── service/                 ← Business logic (@Service classes)
│   │   ├── repository/              ← Spring Data JPA interfaces (@Repository)
│   │   ├── model/                   ← JPA @Entity classes
│   │   ├── dto/                     ← Request/response records or classes
│   │   ├── exception/               ← Custom exceptions + GlobalExceptionHandler
│   │   └── util/                    ← Stateless utility/helper classes
│   └── resources/
│       ├── application.yml          ← Base config
│       ├── application-dev.yml      ← Dev profile overrides
│       └── db/migration/            ← Flyway SQL scripts (V1__init.sql …)
└── test/
    └── java/com/example/app/        ← Mirrors main structure
        ├── controller/              ← MockMvc / @WebMvcTest tests
        ├── service/                 ← Unit tests with Mockito
        └── repository/              ← @DataJpaTest or Testcontainers tests

requirements/                        ← Feature requirement docs (generated by /plan-feature)
docs/                                ← Generated documentation (generated by /document)
```

## Rules

- Controllers must not call repositories directly — always go through a service
- Services must not import from controllers or other services' controllers
- JPA entities live only in `model/` — never used as request/response bodies
- `config/` is the only place to define `@Configuration` and `@ConfigurationProperties` beans
- `exception/` is the only place for `@RestControllerAdvice` handlers
- Test class for `UserService` → `UserServiceTest`; integration test → `UserServiceIT`
- Flyway scripts: `V<version>__<description>.sql` — never edit a script already applied
